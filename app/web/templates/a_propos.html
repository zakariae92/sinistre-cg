À propos

Un gestionnaire reçoit une déclaration : le contrat couvre-t-il ce sinistre ? Ce démonstrateur répond à partir des conditions générales publiques, explique son raisonnement étape par étape, cite les clauses exactes (vérifiées mot pour mot) et signale les ambiguïtés et les informations manquantes plutôt que de trancher à tort.

On ne « chatte » pas avec un PDF

INGESTION (une fois par contrat, idempotente par sha256)
PDF ─► parsing PyMuPDF (blocs, polices, bbox) ─► arbre de clauses ─► Postgres (FTS français + embeddings BGE-M3 locaux)
                                                   └─► extraction LLM : garanties, exclusions, définitions, conditions, plafonds
                                                       chaque ligne pointe vers ses clauses + une citation vérifiée (sinon rejetée)

ANALYSE D'UN SINISTRE
récit ─► 1. faits structurés (inconnu = null) ─► 2. contrat
      ─► 3. récupération ciblée : SQL sur la base structurée (catégorie du sinistre) + définitions + recherche hybride en secours
      ─► 4. raisonnement LLM contraint (JSON strict, citation obligatoire à chaque étape)
      ─► 5. vérification des citations (verbatim / fuzzy ≥ 0,9), un nouvel essai, puis retrait et rétrogradation du verdict
      ─► 6. verdict + ambiguïtés + questions à l'assuré (boucle de clarification)

Choix techniques

  • FastAPI + Pydantic : chaque sortie du LLM est un schéma validé (structured output Gemini).
  • PostgreSQL 17 + pgvector : base structurée, recherche plein texte french et vecteurs dans une seule base.
  • Embeddings BGE-M3 (multilingue FR/EN) servis localement, sans appel externe ; seul le raisonnement appelle l'API Gemini.
  • Référentiel commun de 15 catégories de garanties : c'est lui qui rend comparables des contrats rédigés différemment.
  • Interface Jinja2 + htmx + PDF.js (surlignage des lignes de la clause), sans build JavaScript.
  • Cache Postgres par (contrat, faits, version du prompt) : les exemples sont pré-calculés, la démo est instantanée.

Passer à des centaines de contrats

Ingestion idempotente par sha256 ; même schéma d'extraction et même référentiel pour tous ; versionnage par date d'effet ; file de validation humaine pour les extractions rejetées (data/extraction_rejets.jsonl) ; requêtes SQL transverses (« quels contrats excluent le vol dans les parties communes ? ») ; coût d'ingestion payé une fois par contrat ; coût d'une analyse indépendant de la taille du corpus grâce à la récupération ciblée ; évaluation par contrat pour détecter les régressions.

Limites assumées

  • Seules les conditions générales sont analysées. Les conditions particulières, qui priment, ne sont pas connues : le système le signale et n'affirme jamais une couverture définitive.
  • Montants, plafonds et franchises dépendent souvent des conditions particulières.
  • Les contrats français et belges relèvent d'autres cadres légaux : ils prouvent la généricité du pipeline, pas un conseil.
  • Le parsing PDF est générique (tailles de police, gras, numérotation) : les tableaux et les mises en page en colonnes sont imparfaitement découpés, ce qui se voit dans les fils d'Ariane de certaines clauses.
  • La jurisprudence et les pratiques de gestion ne sont pas couvertes.
